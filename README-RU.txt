CS2 MARKET — локальный проект

Что сделано
- Сайт и API можно запускать на одном Render адресе: backend раздаёт index.html, CSS, JS, config.js и assets, а API доступен на том же origin.
- При запуске через backend config.js автоматически указывает API сайта. В локальном режиме config.js остаётся пустым.
- Для каждого из 20 скинов использованы прозрачные PNG с обрезанными белыми полями.
- Анимация кейса показывает непрерывную загрузку, пока backend выбирает дроп, затем прокручивает ленту и останавливается на фактическом выпавшем скине.
- В Premium написано: для оплаты нужно написать владельцу проекта в личные сообщения Telegram.
- Админ-панель и управление игроками используют SQLite; доступ определяется серверным списком Telegram ID.
- Multiplayer включает поиск игроков, заявки в друзья, приглашения и комнаты с кодами, чатом, историей и синхронизацией состояния через Socket.IO.

Запуск backend локально
1. Установи Node.js 20 или новее.
2. В папке backend скопируй .env.example в .env и укажи BOT_TOKEN от BotFather.
3. В терминале из папки backend выполни npm install, затем npm start.
4. Открой http://localhost:3000. Для Telegram Mini App локальный адрес нужно отдельно опубликовать по HTTPS.

Публикация сайта и API вместе на Render
1. Отправь весь проект в GitHub и создай на Render новый Blueprint из репозитория. render.yaml собирает репозиторий от корня и запускает команды из backend, чтобы frontend-файлы были доступны сервису.
2. В настройках сервиса задай секрет BOT_TOKEN и переменную ADMIN_TELEGRAM_IDS со списком числовых Telegram ID администраторов через запятую (например, 123456789,987654321). Не публикуй их в GitHub и не вставляй во frontend. Пока список пуст, Admin скрыт и admin API возвращает отказ.
3. После деплоя открой адрес Render. Этот же HTTPS адрес укажи как URL Mini App в настройках Telegram-бота.
4. У сервиса включён persistent disk для SQLite. Проверь адрес /health — он должен вернуть ok.

Администратор и Multiplayer
1. Добавь свой числовой Telegram ID в переменную ADMIN_TELEGRAM_IDS в настройках Render. Несколько ID указываются через запятую. Не добавляй ID в frontend или публичный репозиторий.
2. Admin показывается только после ответа backend, а каждый admin API запрос заново проверяет Telegram подпись и whitelist.
3. Multiplayer работает в Telegram Mini App с тем же backend origin. Игроки создают публичные/приватные комнаты, приглашают друзей, общаются в чате и отправляют JSON состояния раунда. Комнаты без активности автоматически закрываются через 30 минут.
4. Статистика и журналы хранятся в SQLite. Результаты одиночных демо-игр отправляются клиентом как статистика; их игровой расчёт в этой версии остаётся на frontend.

Если frontend остаётся на GitHub Pages отдельно от backend
- В config.js укажи публичный URL backend в window.CS2_API_BASE.
- Для backend можно задать FRONTEND_ORIGIN точным origin Pages; если не задавать, API разрешает запросы с любого origin.
- Данные аккаунтов доступны только при запуске Mini App внутри Telegram, поскольку сервер проверяет Telegram initData.
